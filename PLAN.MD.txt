## Step 0: Patch Hardware Sensor & Inset Findings (`:core:sensors` & `:app`)
- [x] **Fix `UPRIGHT_AIMING` Azimuth Projection** (`RotationVectorCompass.kt` & `CompassFusionMath.kt`):
  - Replace chained `remapCoordinateSystem` + Euler `getOrientation()` azimuth with direct 3x3 world rotation-matrix column projection (after display-rotation remapping):
    - `FLAT_MAP`: `azimuthRad = atan2(R[1], R[4])` (projects device `+Y` top edge onto East/North).
    - `UPRIGHT_AIMING`: `azimuthRad = atan2(-R[2], -R[5])` (projects device `-Z` rear camera onto East/North).
  - Trigger `UPRIGHT_AIMING` only when the top edge tilts skyward (`R[7] > sin(55°)` with 5° hysteresis), NOT `|pitch| > 55°`, so nose-down tilts never invert the heading.
  - Add JUnit tests in `CompassAndBarometerMathTest.kt` constructing 3D rotation matrices for headings `0°`, `90°`, `215°`, and `330°` pitched from `0°` through `55°` to `85°` skyward, asserting `< 0.5°` continuity across the posture switch.
- [x] **Fix `BarometerSensor` Trend Datum** (`BarometerSensor.kt`):
  - Compute `pressureTrendInHg` strictly **MSL-to-MSL** (never subtracting a raw station baseline from live MSL). Reset the rolling trend baseline cleanly if GPS altitude lock changes state.
  - Add a unit test verifying `0.00 inHg` trend under constant sea-level pressure across an 80 ft elevation change.
- [x] **Fix `360.0°` Display Rounding** (`AngleMath.kt` / `CompassFusionMath.kt`):
  - Format tenth-degree headings via `Math.floorMod((normalizeDegrees(deg) * 10.0).roundToInt(), 3600) / 10.0` so values like `359.98°` render as `0.0°` and never `360.0°` or `-0.0°`.
- [x] **Edge-to-Edge Window Insets & Friendly Offline Errors**:
  - Apply Material 3 `Scaffold` + `WindowInsets.safeDrawing` (`statusBarsPadding()` / `navigationBarsPadding()`) across all screens so headers never collide with system bars.
  - Map `UnknownHostException` / `IOException` to clean user-facing offline messages (e.g., `"Offline — showing cached forecast from HH:mm"`).
